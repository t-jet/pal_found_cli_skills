# Ontology object set operations

These records describe the `ontology_object_set` commands in `pal-found-ontologies`. Each record gives inputs, behavior, results, and examples.

### ontology_object_set.aggregate

- **Purpose and behavior:** Aggregates the ontology objects present in the `ObjectSet` from the provided object set definition.
- **CLI inputs:** positionals `ontology`; optional `--aggregation`, `--group-by`, `--object-set`, `--accuracy`, `--branch`, `--include-compute-usage`, `--sdk-package-rid`, `--sdk-version`, `--transaction-id`.
- **Input meaning:** `ontology`: Ontology API name or RID; find it with `ontology list` or Ontology Manager. `--object-set`: JSON object-set definition with a `type` discriminator, such as a base set for an object type. `--branch`: The Foundry branch to aggregate the objects from. If not specified, the default branch is used. Branches are an experimental feature and not all workflows are supported. `--accuracy` sets the requested aggregate accuracy mode; `--aggregation` defines the aggregate calculation over the selected objects; `--group-by` groups aggregate results by the specified properties; `--include-compute-usage` includes server compute usage information in the response when true; `--sdk-package-rid` identifies the generated SDK package for SDK-aware requests; `--sdk-version` identifies the generated SDK version paired with that package; `--transaction-id` reads or applies changes in the specified transaction; transaction support is experimental.
- **Input guide:** [Identifiers and JSON payloads](./inputs.md).
- **Preconditions:** The object set definition or RID identifies readable object types and the caller can read their objects.
- **Result:** Returns `AggregateObjectsResponseV2` with the computed aggregate for the selected scope.
- **Failure:** An invalid object-set definition, invalid aggregation, or missing access to an object type returns a structured error.
- **Example:** `pal-found-ontologies ontology-object-set aggregate palantir --aggregation '[{"field":"tenure","name":"min_tenure","type":"min"},{"field":"tenure","name":"avg_tenure","type":"avg"}]' --group-by '[{"field":"startDate","ranges":[{"endValue":"2020-06-01","startValue":"2020-01-01"}],"type":"range"},{"field":"city","type":"exact"}]' --object-set '{"objectType":"Employee","type":"base"}'`

### ontology_object_set.create_temporary

- **Purpose and behavior:** Creates a temporary `ObjectSet` from the given definition. This `ObjectSet` expires after one hour.
- **CLI inputs:** positionals `ontology`; optional `--object-set`, `--branch`, `--sdk-package-rid`, `--sdk-version`.
- **Input meaning:** `ontology`: Ontology API name or RID; find it with `ontology list` or Ontology Manager. `--object-set`: JSON object-set definition with a `type` discriminator, such as a base set for an object type. `--branch`: The Foundry branch to reference. If not specified, the default branch will be used. Branches are an experimental feature and not all workflows are supported. `--sdk-package-rid` identifies the generated SDK package for SDK-aware requests; `--sdk-version` identifies the generated SDK version paired with that package.
- **Input guide:** [Identifiers and JSON payloads](./inputs.md).
- **Preconditions:** The object set definition or RID identifies readable object types and the caller can read their objects.
- **Result:** Returns the created `CreateTemporaryObjectSetResponseV2` with its server-assigned identifier.
- **Failure:** An invalid object-set definition or missing access to an object type prevents creation.
- **Example:** `pal-found-ontologies ontology-object-set create-temporary palantir --object-set '{"type":"base","objectType":"Employee"}'`

### ontology_object_set.get

- **Purpose and behavior:** Gets the definition of the `ObjectSet` with the given RID.
- **CLI inputs:** positionals `ontology`, `object_set_rid`.
- **Input meaning:** `ontology`: Ontology API name or RID; find it with `ontology list` or Ontology Manager. `object_set_rid`: Resource identifier (RID) of the named Foundry resource.
- **Input guide:** [Identifiers and JSON payloads](./inputs.md).
- **Preconditions:** The object set RID exists and the caller can read its definition.
- **Result:** Returns `ObjectSet` for the selected ontology object set.
- **Failure:** An unknown or expired object set RID, or missing read permission, returns a structured error.
- **Example:** `pal-found-ontologies ontology-object-set get palantir ri.object-set.main.object-set.c32ccba5-1a55-4cfe-ad71-160c4c77a053`

### ontology_object_set.load

- **Purpose and behavior:** Load the ontology objects present in the `ObjectSet` from the provided object set definition. For Object Storage V1 backed objects, this endpoint returns a maximum of 10,000 objects. After 10,000 objects have been returned and if more objects are available, attempting to load another page will result in an `ObjectsExceededLimit` error being returned. There is no limit on Object Storage V2 backed objects. Note that null value properties will not be returned. Vector properties will not be returned unless included in the `select` parameter.
- **CLI inputs:** positionals `ontology`; optional `--page-size`, `--page-token`, `--object-set`, `--select`, `--branch`, `--exclude-rid`, `--include-compute-usage`, `--load-property-securities`, `--order-by`, `--sdk-package-rid`, `--sdk-version`, `--select-v2`, `--snapshot`, `--transaction-id`.
- **Input meaning:** `ontology`: Ontology API name or RID; find it with `ontology list` or Ontology Manager. `--object-set`: JSON object-set definition with a `type` discriminator, such as a base set for an object type. `--select`: JSON array of selected property API names or property identifiers, respectively. `--branch`: The Foundry branch to load the object set from. If not specified, the default branch is used. Branches are an experimental feature and not all workflows are supported. `--exclude-rid` omits the object's `__rid` property when true; `--include-compute-usage` includes server compute usage information in the response when true; `--load-property-securities` returns a `propertySecurities` list and secured property values when true (experimental); `--order-by` defines the result sort order using the endpoint's order-by schema; `--page-size` sets the requested maximum entries in one result page; `--page-token` continues from the previous response's `nextPageToken`; omit on the first page; `--sdk-package-rid` identifies the generated SDK package for SDK-aware requests; `--sdk-version` identifies the generated SDK version paired with that package; `--select-v2` selects returned properties using the endpoint's v2 property identifiers; `--snapshot` uses a stable result snapshot across pages when true; live paging may see duplicates or omissions; `--transaction-id` reads or applies changes in the specified transaction; transaction support is experimental.
- **Input guide:** [Identifiers and JSON payloads](./inputs.md).
- **Preconditions:** The object set definition or RID identifies readable object types and the caller can read their objects.
- **Result:** Returns `LoadObjectSetResponseV2` for this ontology object set request.
- **Failure:** Invalid object-set definitions, denied object types, or page limits return errors; a successful empty page means no matches.
- **Example:** `pal-found-ontologies ontology-object-set load palantir --object-set '{"type":"base","objectType":"Employee"}' --select '["name"]'`

### ontology_object_set.load_links

- **Purpose and behavior:** Loads the specified links from the defined object set. Links are defined as a link type API name and object locators for the source and target objects where only the `__primaryKey` and `__apiName` properties are loaded. Links are grouped by source object locator; however, the links for a given source object may be split over multiple entries with the same source object locator. Please keep these limitations in mind: - Links returned may be stale. For example, primary keys returned by this endpoint may not exist anymore. - This endpoint requests links for 1,000 objects at a time. If, for any page of 1,000 objects, there are more than 100,000 links present, results are limited to 100,000 links and should be considered partial. - This endpoint does not support OSv1 links and will return an error if links provided are backed by OSv1.
- **CLI inputs:** positionals `ontology`; optional `--page-token`, `--links`, `--object-set`, `--branch`, `--include-compute-usage`, `--preview`, `--sdk-package-rid`, `--sdk-version`.
- **Input meaning:** `ontology`: Ontology API name or RID; find it with `ontology list` or Ontology Manager. `--object-set`: JSON object-set definition with a `type` discriminator, such as a base set for an object type. `--branch`: The Foundry branch from which to load the links. If not specified, the default branch is used. Branches are an experimental feature and not all workflows are supported. `--include-compute-usage` includes server compute usage information in the response when true; `--links` describes which links to load from the object set; `--page-token` continues from the previous response's `nextPageToken`; omit on the first page; `--preview` enables endpoint preview behavior when that feature is available; `--sdk-package-rid` identifies the generated SDK package for SDK-aware requests; `--sdk-version` identifies the generated SDK version paired with that package.
- **Input guide:** [Identifiers and JSON payloads](./inputs.md).
- **Preconditions:** The object set definition or RID identifies readable object types and the caller can read their objects.
- **Result:** Returns `LoadObjectSetLinksResponseV2` for this ontology object set request.
- **Failure:** Invalid object-set definitions, denied object types, or page limits return errors; a successful empty page means no matches.
- **Example:** `pal-found-ontologies ontology-object-set load-links palantir --links '["directReport"]' --object-set '{"objectType":"Employee","type":"base"}'`

### ontology_object_set.load_multiple_object_types

- **Purpose and behavior:** Load the ontology objects present in the `ObjectSet` from the provided object set definition. The resulting objects may be scoped to an object type, in which all the selected properties on the object type are returned, or scoped to an interface, in which only the object type properties that implement the properties of any interfaces in its scope are returned. For objects that are scoped to an interface in the result, a mapping from interface to object implementation is returned in order to interpret the objects as the interfaces that they implement. For Object Storage V1 backed objects, this endpoint returns a maximum of 10,000 objects. After 10,000 objects have been returned and if more objects are available, attempting to load another page will result in an `ObjectsExceededLimit` error being returned. There is no limit on Object Storage V2 backed objects. Note that null value properties will not be returned.
- **CLI inputs:** positionals `ontology`; optional `--page-size`, `--page-token`, `--object-set`, `--select`, `--branch`, `--exclude-rid`, `--include-compute-usage`, `--load-property-securities`, `--order-by`, `--preview`, `--sdk-package-rid`, `--sdk-version`, `--select-v2`, `--snapshot`, `--transaction-id`.
- **Input meaning:** `ontology`: Ontology API name or RID; find it with `ontology list` or Ontology Manager. `--object-set`: JSON object-set definition with a `type` discriminator, such as a base set for an object type. `--select`: JSON array of selected property API names or property identifiers, respectively. `--branch`: The Foundry branch to load the object set for multiple object types. If not specified, the default branch is used. Branches are an experimental feature and not all workflows are supported. `--exclude-rid` omits the object's `__rid` property when true; `--include-compute-usage` includes server compute usage information in the response when true; `--load-property-securities` returns a `propertySecurities` list and secured property values when true (experimental); `--order-by` defines the result sort order using the endpoint's order-by schema; `--page-size` sets the requested maximum entries in one result page; `--page-token` continues from the previous response's `nextPageToken`; omit on the first page; `--preview` enables endpoint preview behavior when that feature is available; `--sdk-package-rid` identifies the generated SDK package for SDK-aware requests; `--sdk-version` identifies the generated SDK version paired with that package; `--select-v2` selects returned properties using the endpoint's v2 property identifiers; `--snapshot` uses a stable result snapshot across pages when true; live paging may see duplicates or omissions; `--transaction-id` reads or applies changes in the specified transaction; transaction support is experimental.
- **Input guide:** [Identifiers and JSON payloads](./inputs.md).
- **Preconditions:** The object set definition or RID identifies readable object types and the caller can read their objects.
- **Result:** Returns `LoadObjectSetV2MultipleObjectTypesResponse` for this ontology object set request.
- **Failure:** Invalid object-set definitions, denied object types, or page limits return errors; a successful empty page means no matches.
- **Example:** `pal-found-ontologies ontology-object-set load-multiple-object-types palantir --object-set '{"type":"base","objectType":"Employee"}' --select '["name"]'`

### ontology_object_set.load_objects_or_interfaces

- **Purpose and behavior:** Load the ontology objects present in the `ObjectSet` from the provided object set definition. If the requested object set contains interfaces and the object can be viewed as an interface, it will contain the properties defined by the interface. If not, it will contain the properties defined by its object type. This allows directly loading all objects of an interface where all objects are viewed as the interface, for example. Note that the result object set cannot contain a mix of objects with "interface" properties and "object type" properties. Attempting to load an object set like this will result in an error. For Object Storage V1 backed objects, this endpoint returns a maximum of 10,000 objects. After 10,000 objects have been returned and if more objects are available, attempting to load another page will result in an `ObjectsExceededLimit` error being returned. There is no limit on Object Storage V2 backed objects.
- **CLI inputs:** positionals `ontology`; optional `--page-size`, `--page-token`, `--object-set`, `--select`, `--branch`, `--exclude-rid`, `--order-by`, `--preview`, `--sdk-package-rid`, `--sdk-version`, `--select-v2`, `--snapshot`, `--transaction-id`.
- **Input meaning:** `ontology`: Ontology API name or RID; find it with `ontology list` or Ontology Manager. `--object-set`: JSON object-set definition with a `type` discriminator, such as a base set for an object type. `--select`: JSON array of selected property API names or property identifiers, respectively. `--branch`: The Foundry branch to load the objects or interfaces from. If not specified, the default branch is used. Branches are an experimental feature and not all workflows are supported. `--exclude-rid` omits the object's `__rid` property when true; `--order-by` defines the result sort order using the endpoint's order-by schema; `--page-size` sets the requested maximum entries in one result page; `--page-token` continues from the previous response's `nextPageToken`; omit on the first page; `--preview` enables endpoint preview behavior when that feature is available; `--sdk-package-rid` identifies the generated SDK package for SDK-aware requests; `--sdk-version` identifies the generated SDK version paired with that package; `--select-v2` selects returned properties using the endpoint's v2 property identifiers; `--snapshot` uses a stable result snapshot across pages when true; live paging may see duplicates or omissions; `--transaction-id` reads or applies changes in the specified transaction; transaction support is experimental.
- **Input guide:** [Identifiers and JSON payloads](./inputs.md).
- **Preconditions:** The object set definition or RID identifies readable object types and the caller can read their objects.
- **Result:** Returns `LoadObjectSetV2ObjectsOrInterfacesResponse` for this ontology object set request.
- **Failure:** Invalid object-set definitions, denied object types, or page limits return errors; a successful empty page means no matches.
- **Example:** `pal-found-ontologies ontology-object-set load-objects-or-interfaces palantir --object-set '{"type":"interfaceBase","interfaceType":"Person"}' --select '["name"]'`
